2.1 设计意图

T2 原有的 HSTU_FWD_MINIMAL_INSTANCES 是一个 (kUseSoftmax, kHasDropout) 二维开关，只保留 (false,false) 这一格 = 48 个实例。要验证全部 no-softmax 面，需要保留 kUseSoftmax==false 的整列（含 dropout）= 96 个实例。因此按原有机制的风格加一个更宽的变体，而不是重构它（§6 简单优先 / §7 改动最小化）。

该元素容差

7对 HANDOFF 的订正

7.1 gpu_busy_percent = 100 是假信号，不能当 wedge 指标

HANDOFF §3.4 把「GPU% = 100 恒定（8 个 XCC 全满）」列为 MES wedge 的旁证。实测推翻：

状态证据gpu_busy_percent
完全空闲/sys/class/kfd/kfd/proc/ 为空，ps 中无任何 GPU 进程100 ×10 次采样
满负载HSTU fwd b=8/nh=8/seq=4096 跑 perf100 ×8 次采样
结论：在 gfx1250 上 gpu_busy_percent（以及 rocm-smi 的 GPU%）恒为 100，与实际负载无关， 是基线行为而非 wedge 特征。后续任何人照着这个指标判 wedge 一定会误判。 §3.4 里其余旁证（温度/功耗/SCLK 零波动、rls 显示 No active runlist、 amdgpu_fence_info 无推进）不受影响，仍然有效。

附带两点：
① 本次 rocm-smi 的 power 读数在 1574–2142 W、SCLK 在 1321–2312 MHz 之间变化过 （不像 GPU% 那样恒定）—— 但这只是两次非受控采样的差异，本次未对这两项做负载对照实验， 因此不能据此断言它们可以替代 GPU% 当 wedge 指标。推断，未核实
② /sys/kernel/debug/kfd/rls 在容器重建后不存在（debugfs 未挂载）， §6.2 的辅助确认命令需先 mount -t debugfs none /sys/kernel/debug 才能用。
